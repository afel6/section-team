Build a small HTTP JSON service for polls: people create a poll with a question and options, vote once each, may take their vote back, and the poll can be closed. It is one Node.js process started as `node server.mjs` from the project root (put `server.mjs` next to `package.json`), and it keeps all its data in a single file. It has no browser page.

Running
- Environment: `PORT` (default 3000) and `DATA_FILE` (default `polls.json`). The server listens on 127.0.0.1 only. Once it accepts connections it writes `listening on http://127.0.0.1:<port>` and a newline to stdout, where `<port>` is the port it actually listens on (so `PORT=0` prints the port the system chose).
- At start, a `DATA_FILE` that does not exist is an empty service (no polls). A `DATA_FILE` that exists but cannot be read (for example a directory) or does not hold data this server wrote (for example an empty file or text that is not JSON) makes the server write `cannot load <DATA_FILE>` and a newline to stderr, where `<DATA_FILE>` is the value as given, and exit with code 1 without listening.
- Every change (creating a poll, a vote, taking a vote back, closing a poll) is written to `DATA_FILE` before its reply is sent, so a server started again on the same file, even after the first one was killed right after the reply, sees every change that got a 2xx reply, and gives the next poll the next id. If writing the file fails, the reply is 500 `{"error": "cannot save"}` and the change is not made (later requests see the service as it was before it).
- Requests that arrive at the same time give the same replies and the same final data as if they had arrived one after the other in some order: no change is lost, and none is made twice.

Replies
- Every reply other than 204 has a JSON body and the header `content-type: application/json; charset=utf-8`. A 204 reply has no body.
- Every error reply is `{"error": "<message>"}` with the message named below.

Routes

| Route | Body | Success |
|---|---|---|
| `POST /polls` | `{"question", "options"}` | 201 the poll |
| `GET /polls` | | 200 `{"polls": [<summary>, ...]}` |
| `GET /polls/:id` | | 200 the poll |
| `POST /polls/:id/votes` | `{"voter", "option"}` | 201 `{"poll": <id>, "voter": <voter>, "option": <option>}` |
| `DELETE /polls/:id/votes/:voter` | | 204 |
| `POST /polls/:id/close` | | 200 the poll, now closed |

- A poll is shown as `{"id": <id>, "question": <question>, "options": [...], "closed": <boolean>, "results": [{"option": <option>, "votes": <n>}, ...], "total": <n>}`, with `results` holding every option in the poll's order with its number of votes, and `total` the number of votes in the poll. A summary is `{"id", "question", "closed", "total"}` with the same values.
- Poll ids are the integers 1, 2, 3, ... in the order polls are created, never reused.
- `GET /polls` lists every poll's summary, sorted by id. When the query has a `status` parameter (the first one, if there are several), its value must be `open` or `closed` and only polls with that state are listed; any other value, the empty string included, gets 400 `status must be open or closed`. Other query parameters are ignored, on every route.
- A new poll is open, with no votes. A vote is `{"voter", "option"}`; each voter has at most one vote per poll. `DELETE` removes the vote of `:voter` from the poll. A closed poll stays closed and keeps its votes.

Rules
- `question`: a string that, after removing white space at both ends (JavaScript's `trim()`), has 1 to 200 characters (JavaScript string length); it is stored and shown trimmed. Otherwise 400 `question must be a string of 1 to 200 characters`.
- `options`: an array of 2 to 10 strings, each of which, after `trim()`, has 1 to 100 characters, and no two of which are the same after `trim()` and `toLowerCase()`. They are stored and shown trimmed, in the given order. Otherwise 400 `options must be 2 to 10 different strings of 1 to 100 characters`.
- `voter` (in a vote body): a string of 1 to 32 characters, each of `a-z`, `0-9` and `_`. Otherwise 400 `voter must be 1 to 32 characters of a-z, 0-9 and _`.
- `option` (in a vote body): a string, else 400 `option must be a string`; and exactly equal (no trimming, letter case matters) to one of the poll's options as stored, else 400 `unknown option`.
- A poll holds at most 100 votes.
- A field that is missing breaks its rule like any other bad value; `null` is a bad value too.

Request handling. The checks run in this order, and the first one that fails decides the reply; a failed request changes nothing.
1. The route, matched on the path (the part before any `?`) exactly as written, without decoding `%` escapes: `/polls`, `/polls/<a>`, `/polls/<a>/votes`, `/polls/<a>/votes/<b>` and `/polls/<a>/close`, where `<a>` and `<b>` are any non-empty segments without `/`. Any other path (for example `/`, `/polls/`, `/polls//close` or `/polls/1/votes/`) gets 404 `not found`. A path that matches but whose method is not in the table gets 405 `method not allowed`, with an `Allow` header listing that path's methods: `GET, POST` for `/polls`, `GET` for `/polls/<a>`, `POST` for `/polls/<a>/votes` and `/polls/<a>/close`, `DELETE` for `/polls/<a>/votes/<b>`.
2. For the two routes with a body (`POST /polls` and `POST /polls/:id/votes`): a body of more than 16384 bytes gets 413 `body too large` (16384 bytes are accepted); a body that is not valid UTF-8, or that `JSON.parse` rejects (an empty body, and a body starting with a byte order mark, included) gets 400 `invalid JSON`; a JSON value that is not an object (null, an array, a string, a number, a boolean) gets 400 `body must be a JSON object`; a body with a field other than the route's two gets 400 `unknown field <name>`, naming the first such field in the order `Object.keys` lists them. Then the fields, in this order: `question`, then `options` for a poll; `voter`, then `option must be a string` for a vote. Any body sent to the other routes is ignored.
3. For `GET /polls`: the `status` parameter.
4. `:id` must be the id of an existing poll, written in decimal without leading zeros or signs (`/polls/01`, `/polls/+1`, `/polls/1.0` and `/polls/abc` name no poll); otherwise 404 `poll not found`.
5. For a vote: an `option` that is not one of the poll's options gets 400 `unknown option`.
6. For a vote, taking a vote back, or closing: a closed poll gets 409 `poll closed`.
7. For a vote: a voter who already has a vote in the poll gets 409 `already voted`; then a poll that already holds 100 votes gets 409 `poll is full`. For taking a vote back: when `:voter` (compared exactly as written in the path) has no vote in the poll, 404 `vote not found`.
8. Saving the change (500 `cannot save`).
