Build a cron schedule library `cron.mjs` (an ES module with the named exports `parseCron`, `nextRuns` and `CronError`; no default export is needed) and a command-line tool `cron-cli.mjs` (an ES module, run as `node cron-cli.mjs <expression> [--from <time>] [--count <n>]`) that prints the next times a cron expression fires. Put both files at the project root, next to `package.json`. All times are UTC; there is no time zone or daylight saving handling. Throughout, a "string" is a primitive string (`typeof` is `'string'`).

Expressions
- An expression has exactly 5 fields: minute, hour, day-of-month, month and day-of-week, in that order. Spaces and tabs at the start and end are ignored, and fields are separated by one or more spaces or tabs. Every other character, a newline or a non-breaking space included, is part of a field.
- The fields take these values: minute 0 to 59, hour 0 to 23, day-of-month 1 to 31, month 1 to 12, day-of-week 0 to 7, where both 0 and 7 mean Sunday.
- A field is a list of one or more items separated by `,`. An item is a base, optionally followed by `/` and a step. A base is `*`, a single value `a`, or a range `a-b`. A step is 1 or 2 ASCII digits with a value of at least 1.
- A value is 1 or 2 ASCII digits (so `05` is 5 and `005` is not a value), and must lie within the field's values. In the month field a value may also be a month name `JAN` to `DEC` (1 to 12), and in the day-of-week field a weekday name `SUN` to `SAT` (0 to 6); names are exactly 3 letters, in any letter case (`mon`, `Mon`, `MON`), and may be used as either end of a range. Names are not allowed in other fields or as a step.
- A range `a-b` needs `a` not greater than `b` (after names are turned into numbers; so `MON-FRI` is 1-5, `5-7` is valid and `7-SUN` is not).
- An item stands for these values: `*` is every value of the field (0 to 7 for day-of-week); `a` is `a`; `a-b` is `a` to `b`; with a step `s`, the base's first value and every `s`-th value after it up to the base's last value, where a single value `a` with a step runs up to the field's highest value (`5/20` in minutes is 5, 25 and 45; `*/2` in hours is 0, 2, ..., 22). In the day-of-week field, 7 then counts as 0 (so `5-7` is 0, 5 and 6, and `1/3` is 0, 1 and 4).
- A field stands for every value of any of its items.

`parseCron(expr)`
- If `expr` is not a string, throw a `TypeError` with the message `expression must be a string`.
- If there are not exactly 5 fields, throw a `CronError` with the message `expected 5 fields, got <n>` (an empty or all-blank string has 0 fields) and `field` null.
- Otherwise, the first field (in field order) that breaks any rule above makes it throw a `CronError` with the message `invalid <name> field: <text>`, where `<name>` is `minute`, `hour`, `day-of-month`, `month` or `day-of-week` and `<text>` is the field exactly as written; its `field` property is `<name>`. Examples of broken fields: an empty item (`1,,2`, `1,`), `60` as a minute, `0` as a day-of-month, `*/0`, `*/100`, `1/2/3`, `*-5`, `5-`, `-5`, `10-5`, `L`, `?`, `JAN` outside the month field, `January`.
- On success, return a new object `{minute, hour, dayOfMonth, month, dayOfWeek, dayOfMonthStar, dayOfWeekStar}`: each of the first five is a new array of the field's distinct values in ascending order (day-of-week never contains 7), and `dayOfMonthStar` and `dayOfWeekStar` are true when that field's text starts with `*`, false otherwise.
- `CronError` is a subclass of `Error` whose `name` is `CronError`.

`nextRuns(expr, from, count)`
- The arguments are checked in this order, and the first failure throws: `expr` as `parseCron` checks it (the same errors); `from` must be a `Date` (`instanceof Date`) whose time is not NaN, else a `TypeError` with the message `from must be a valid Date`; `count` must be an integer number (`Number.isInteger`) from 1 to 1000, else a `RangeError` with the message `count must be an integer from 1 to 1000`. The tests only pass a `from` whose UTC year is 1970 to 9899.
- It returns a new array of new `Date` objects: the first `count` runs strictly after `from`, in ascending order. A run is the start of a UTC minute (seconds and milliseconds 0) whose minute, hour and month are in their fields' values, and whose day matches: when `dayOfMonthStar` or `dayOfWeekStar` is true, the day must match both the day-of-month and the day-of-week values; when both are false, it must match at least one of them. So `0 0 13 * FRI` fires on every 13th and every Friday, while `0 0 */2 * FRI` fires only on Fridays with an odd day of the month.
- "Strictly after" compares exact times: from 10:00:00.000 the first candidate is 10:01, and from 09:59:59.999 it is 10:00.
- Runs whose UTC year is more than 100 above the UTC year of `from` are never returned. When fewer than `count` runs exist up to that limit, it returns the ones that do (possibly none): `0 0 30 2 *` gives `[]`.
- Each call returns within 2 seconds, whatever the arguments.
- Neither function changes its arguments.

Command line
- `node cron-cli.mjs <expression> [--from <time>] [--count <n>]`. The arguments are read left to right: `--from` and `--count` each take the next argument as their value, whatever it is; any other argument that starts with `--` is unknown; every other argument (including one that starts with a single `-`, or the empty string) is the expression.
- `--from` is `YYYY-MM-DDTHH:MM` or `YYYY-MM-DDTHH:MM:SS`, followed by `Z`: a real calendar date with a year from 1970 to 9899, an hour 00 to 23, and minutes and seconds 00 to 59. Without `--from`, the current time is used. `--count` is one or more ASCII digits with a value from 1 to 1000 (leading zeros allowed); without it, the count is 5.
- On success it writes each run on its own line as `YYYY-MM-DD HH:MM Ddd`, where `Ddd` is the UTC weekday `Sun`, `Mon`, `Tue`, `Wed`, `Thu`, `Fri` or `Sat` (for example `2026-11-20 09:00 Fri`), followed by "\n", writes nothing to stderr, and exits 0.
- The checks run in this order, and the first failure decides the reply. Each failure writes exactly one line ending in "\n" to stderr:
  1. The arguments: no expression, more than one expression, an unknown option, an option without a value, or an option given twice: `usage: node cron-cli.mjs <expression> [--from <time>] [--count <n>]`, nothing on stdout, exit 2.
  2. A bad `--from` value: `error: invalid --from: <value>`, nothing on stdout, exit 2.
  3. A bad `--count` value: `error: invalid --count: <value>`, nothing on stdout, exit 2.
  4. A bad expression (a `CronError`): `error: <message>` (for example `error: invalid hour field: 24`), nothing on stdout, exit 3.
  5. Fewer runs than the count within the 100-year limit: the runs that were found are written to stdout as on success, then `error: only <k> of <n> runs within 100 years` to stderr, exit 1 (with `<k>` 0, stdout is empty).
