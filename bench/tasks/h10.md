Build a quick-polls app: an HTTP server `server.mjs` (an ES module, run as `node server.mjs`) that serves a JSON API and a browser page, and keeps its data in one JSON file. Anyone can create a poll, vote on it, close it or delete it; there are no accounts.

Server
- It listens on 127.0.0.1 at the port in the `PORT` environment variable. An unset or empty `PORT` means 3000. A `PORT` that is not made only of ASCII digits 0-9, or whose value is above 65535, or a port that cannot be bound (for example because it is in use), makes the server write one line of its choice to stderr and exit with code 1.
- Once listening, it prints `listening on http://127.0.0.1:<port>` followed by "\n" to stdout, where `<port>` is the port actually bound (with `PORT=0`, the port the OS picked). This line is the only thing the server ever writes to stdout.
- Its data lives in the file named by the `DATA_FILE` environment variable, as JSON in a layout of your choice. An unset or empty `DATA_FILE` means `polls.json`. A relative `DATA_FILE`, the default included, is resolved against the current working directory.
- The server reads the data file once, at startup, before it listens. If the file, or a folder on its path, does not exist, there are no polls yet. If reading it fails in any other way (for example the path is a directory), or its content is not data in the layout this server writes (for example it is empty or not valid JSON), the server writes `cannot read data file <name>` followed by "\n" to stderr, where `<name>` is the value of `DATA_FILE` as given (`polls.json` when it is unset or empty), and exits with code 1 without listening.
- After startup the server's memory is the truth: changes made to the file from outside are not noticed. The server writes the data file only when a request changes something (a poll created, a vote counted, a poll closed or deleted), never for any other request, and it never creates folders. Every change is saved before its reply is sent: after a restart with the same `DATA_FILE`, the polls, their votes, who voted on each poll, and the id the next poll will get are as before.
- If saving a change fails (for example because the data file's folder does not exist), the reply is 500 `internal error` and nothing changes, the next id included. Any other unexpected failure while handling a request also replies 500 `internal error`. In both cases the server keeps running.
- Requests that arrive at the same time give the same result as if they had been handled one at a time in some order: of several votes by the same voter sent at once to one open poll, exactly one is counted, and no poll id is given twice.
- Before sending any reply, the server reads the whole request body, if there is one, so the client always receives the reply, the 413 and 415 replies included.

API
- Only the parsed JSON of a reply body matters: white space and key order in it are free. Every reply with a body, other than the page and the script, has `Content-Type: application/json; charset=utf-8`. An error reply is `{"error": "<message>"}` with exactly that key, where `<message>` is the text given here.
- A request's path is its request target up to the first `?`. Routes compare the path byte for byte, with no percent-decoding and no dot-segment, slash or letter-case normalisation. The query is ignored.
- A poll is shown as `{"id": <number>, "question": <string>, "closed": <boolean>, "total": <number>, "answers": [{"text": <string>, "votes": <number>, "percent": <number>}, ...]}` with exactly these keys, the answers in the order they were given, and `total` the number of votes on the poll. The first poll gets id 1 and each new poll the next integer; an id is never given twice, even after deletes and restarts.
- Percentages: when `total` is 0, every `percent` is 0. Otherwise every `percent` is a whole number and together they add up to exactly 100: each answer first gets `floor(100 * votes / total)`, then the points still missing up to 100 go, one each, to the answers with the largest remainders `(100 * votes) % total`, and among equal remainders to the earlier answer. For example votes 1, 1, 1 give 34, 33, 33, and votes 2, 1 give 67, 33.
- `GET /api/polls`: 200 `{"polls": [...]}` with every poll as shown above, newest first (the highest id first).
- `POST /api/polls` with a JSON body holding `question` and `answers`: 201 and the new poll, open and with no votes.
- `GET /api/polls/<id>`: 200 and the poll.
- `POST /api/polls/<id>/votes` with a JSON body holding `voter` and `answer`: 201 and the poll with the vote counted.
- `POST /api/polls/<id>/close`: 200 and the poll, now closed. Closing a poll that is already closed replies 200 with the poll as it is and changes nothing. A request body, if any, is ignored.
- `DELETE /api/polls/<id>`: 204 with an empty body, and the poll and its votes are gone.
- In these routes `<id>` is any non-empty text holding no `/`. When `<id>` is not a positive integer written in ASCII digits 0-9 without a leading zero, or no poll has that id, the reply is 404 `poll not found`.
- `GET /` and `GET /app.js` serve the page (see Page).
- Any other path: 404 `not found`, whatever the method. A path above with a method not listed for it (HEAD and OPTIONS included): 405 `method not allowed`; the 405 wins over 404 `poll not found`, so `PUT /api/polls/abc` is 405.

Rules for `POST /api/polls` and `POST /api/polls/<id>/votes` (the first rule that fails decides the reply)
1. For the votes route, `<id>` names no poll: 404 `poll not found`, as said above.
2. The media type of the `Content-Type` header (the part before the first `;`, with spaces and tabs removed from both ends, letter case ignored) is not `application/json`, or the header is missing: 415 `content type must be application/json`.
3. The body is longer than 10000 bytes, counting the bytes actually received: 413 `body too large`.
4. The body, decoded as `Buffer.prototype.toString('utf8')` does and then given to `JSON.parse`, is not a JSON object (it is empty, not valid JSON, `null`, an array, a string, a number or a boolean): 400 `body must be a JSON object`. A byte order mark at the very start is kept, so such a body is not valid JSON.
- Then, for a new poll:
  5. `question` is not a string, or is shorter than 1 or longer than 200 UTF-16 code units after removing the white space at both ends (as `String.prototype.trim` does): 400 `question must be 1 to 200 characters`.
  6. `answers` is not an array (as `Array.isArray` decides) of 2 to 6 items: 400 `answers must be a list of 2 to 6 items`.
  7. An item of `answers` is not a string, or is shorter than 1 or longer than 80 UTF-16 code units after trimming: 400 `each answer must be 1 to 80 characters`.
  8. Two items of `answers` are the same after trimming and lowering the letter case (as `toLowerCase` does): 400 `answers must be different`.
  - The poll keeps the trimmed question and the trimmed answers. Other keys in the body are ignored.
- Then, for a vote:
  5. `voter` is not a string, or is shorter than 1 or longer than 40 UTF-16 code units after trimming: 400 `voter must be 1 to 40 characters`.
  6. `answer` is not a number that is an integer (as `Number.isInteger` decides) from 0 to the number of answers minus 1: 400 `answer must be the number of an answer, counting from 0`.
  7. The poll is closed: 409 `poll is closed`.
  8. This poll already has a vote by a voter whose name is the same after trimming and lowering the letter case: 409 `already voted`.
  - The vote counts for the answer at that index. Other keys in the body are ignored.

Page
- `GET /` answers 200 with `Content-Type: text/html; charset=utf-8` and the page. `GET /app.js` answers 200 with `Content-Type: text/javascript; charset=utf-8` and the page's script.
- The page loads the script with a `<script>` element whose `src` is exactly `/app.js`, with no `type`, `defer` or `async` attribute, placed as the last element in `<body>`. The script is a classic script (no `import` or `export`) and does its setup at once, without waiting for any load event.
- All of the page's code is in `/app.js`: the page has no inline script and no `on...` event attributes. Neither the page nor the script contains `http://` or `https://`.
- Of the browser's APIs, the script uses only `fetch` (with the `method`, `headers` and `body` options, and the reply's `status` and `json()`), `document.getElementById`, `document.createElement`, the `textContent`, `value`, `type`, `disabled`, `append`, `replaceChildren` and `addEventListener` members of elements, and `preventDefault` of events.
- The HTML elements named below are checked by their tag, attributes and text, not by exact markup: attribute order, quoting and extra attributes are free.
- The page's `<title>` and its only `<h1>` both have the text `Quick polls`.
- The page holds a `<form id="poll-form">` with the `novalidate` attribute. Inside it are `<input type="text" id="question" name="question">`, `<textarea id="answers" name="answers">` and `<button type="submit" id="create">` with the text `Create poll`. The two fields each have their own `<label for="<id>">`, which does not contain the field, with exactly this text: `Question` for `#question`, `Answers, one per line` for `#answers`.
- Outside the form, the page holds `<ul id="poll-list">`; `<h2 id="poll-question">`, which is empty; `<ul id="results">`, which is empty; `<input type="text" id="voter">` with its own `<label for="voter">`, which does not contain it, with exactly the text `Your name`; `<button type="button" id="close-poll">` with the text `Close poll` and the `disabled` attribute; and `<p id="error" role="alert">`, which is empty.
- Every value is shown as plain text, never as HTML: a question `<b>x</b>` shows those 8 characters.
- Requests use path-only URLs exactly as written here: `/api/polls`, `/api/polls/<id>`, `/api/polls/<id>/votes` and `/api/polls/<id>/close`.
- A reply has an error status when its status is not the success status of its request: 200 for `GET /api/polls`, `GET /api/polls/<id>` and the close request, 201 for creating a poll and for a vote. The reply's error message is the body's `error` value when the body is a JSON object whose `error` is a string, and `Request failed.` otherwise. A reply whose body cannot be read or parsed as JSON counts as no reply. A request that gets no reply at all (for example because the server is down) shows `Could not reach the server.` in `#error`.
- The list: when the page loads, and each time the rules below say the list is fetched again, the script requests `GET /api/polls` and replaces the content of `#poll-list` with one `<li>` per poll in the reply's order. Each `<li>` has exactly two child nodes: a text node with exactly the text `<question> (<total> votes)`, or `<question> (<total> votes, closed)` for a closed poll, and then a `<button type="button">` with the text `Open`. With no polls, the list holds a single `<li>` whose only child is a text node `No polls yet.`. A list fetch that gets an error status shows the reply's error message in `#error`, one that gets no reply shows `Could not reach the server.`, and both leave the list as it was; one that succeeds leaves `#error` alone.
- Showing a poll: the script sets the text of `#poll-question` to the poll's question, replaces the content of `#results` with one `<li>` per answer, in order, each with exactly two child nodes, a text node with exactly the text `<text>: <votes> (<percent>%)` and then a `<button type="button">` with the text `Vote`, which is disabled when the poll is closed and enabled otherwise, and enables `#close-poll` when the poll is open and disables it when it is closed. The poll shown is the one the next vote or close is for.
- Open: clicking an `Open` button requests `GET /api/polls/<id>` for its poll. On 200 the poll in the reply is shown and `#error` is emptied. Otherwise `#error` shows the reply's error message, or `Could not reach the server.` with no reply, and what is shown stays as it was.
- Vote: clicking a `Vote` button disables it, then sends `POST /api/polls/<id>/votes` for the poll shown, with exactly the header `Content-Type: application/json` and a JSON body whose `voter` is the current value of `#voter`, unchanged (not trimmed), and whose `answer` is the index of that button's answer. The script never checks the name itself. When the request settles, the button is enabled again. On 201 the poll in the reply is shown, `#error` is emptied and the list is fetched again. Otherwise `#error` shows the reply's error message (for example `already voted`), or `Could not reach the server.` with no reply, and what is shown stays as it was.
- Close: clicking `#close-poll` disables it and sends `POST /api/polls/<id>/close` for the poll shown, with no body. On 200 the poll in the reply is shown, `#error` is emptied and the list is fetched again. Otherwise `#close-poll` is enabled again and `#error` shows the reply's error message, or `Could not reach the server.` with no reply.
- Creating: a submit event on the form never reloads the page (the script calls `preventDefault`). A submit while `#create` is disabled sends nothing. Otherwise the script disables `#create`, then sends `POST /api/polls` with exactly the header `Content-Type: application/json` and a JSON body whose `question` is the current value of `#question`, unchanged, and whose `answers` are the lines of `#answers`: its value split at each "\n", with one "\r" at the end of a line removed, leaving out every line that is empty or only white space (as `String.prototype.trim` says), and keeping the other lines unchanged (not trimmed), in order. The script never checks the fields itself. `#create` is enabled again as soon as the request settles, before anything else happens. On 201 `#question` and `#answers` are emptied, `#error` is emptied, the new poll in the reply is shown and the list is fetched again. Otherwise `#error` shows the reply's error message, or `Could not reach the server.` with no reply, and the form stays as it was.
