Build an arithmetic expression library `calc.mjs` (an ES module with the named exports `evaluate` and `CalcError`; no default export is needed) and a command-line tool `calc-cli.mjs` (an ES module, run as `node calc-cli.mjs <expression> [<name>=<value>]...`) that prints the value of an expression. Put both files at the project root, next to `package.json`.

Tokens
- `evaluate(source, vars)` first splits the whole `source` into tokens, from left to right, before it parses anything. White space (space, tab, CR and LF) separates tokens and is otherwise ignored. At each point the longest text that forms a token is taken.
- A number is one or more ASCII digits 0-9, then optionally `.` and one or more digits, then optionally `e` or `E`, an optional `+` or `-`, and one or more digits: `7`, `007`, `0.5`, `12.75e-3` and `1E6` are numbers. Its value is what `Number()` gives for its text. So `5.` is the number `5` followed by `.`, and `1e3x` is the number `1e3` followed by the name `x`.
- A name is an ASCII letter or `_`, followed by any number of ASCII letters, digits and `_`.
- The other tokens are `+`, `-`, `*`, `/`, `%`, `^`, `(`, `)` and `,`.
- A character that cannot start a token (for example `.`, `#`, `"` or a no-break space) fails with `unexpected character <c> at <i>`, where `<c>` is `JSON.stringify` of that character (the whole character, both halves of a surrogate pair included) and `<i>` is its position.
- A number whose value is not finite (for example `1e400`) fails with `number too large at <i>`.
- Positions count UTF-16 code units of `source` from 0, as JavaScript string indexes do. The position of a token is the position of its first character.

Grammar (from the loosest binding to the tightest)
```
expression := term (("+" | "-") term)*
term       := unary (("*" | "/" | "%") unary)*
unary      := ("+" | "-") unary | power
power      := primary ("^" unary)?
primary    := number | name | name "(" arguments? ")" | "(" expression ")"
arguments  := expression ("," expression)*
```
- So `+` and `-`, then `*`, `/` and `%`, work from left to right: `10-3-2` is 5. `^` works from right to left and binds tighter than a sign before it: `2^3^2` is 512, `-2^2` is -4, `2^-1` is 0.5 and `(-2)^2` is 4. Signs may repeat: `--2` is 2.
- A name followed by `(` is a function call; any other name is a variable. There is no implicit multiplication: `2(3)`, `2x` and `(1)(2)` are errors.
- A token where the grammar does not allow one fails with `unexpected <token> at <i>`, where `<token>` is `number <text>` for a number, `name <text>` for a name, and the token itself in double quotes for any other token, with `<text>` the token's text as written in `source`: for example `unexpected ")" at 4`, `unexpected number 2 at 2`, `unexpected name x at 1`. When `source` ends where the grammar needs more (an empty `source` or one that is only white space included) the message is `unexpected end of input`.
- Functions: `abs(x)`, `sqrt(x)`, `round(x)`, `min(x, ...)` and `max(x, ...)`. `abs`, `sqrt` and `round` take exactly 1 argument; `min` and `max` take 1 or more. A call of any other name fails with `unknown function <name> at <i>` as soon as its name and `(` are read. A call with the wrong number of arguments fails as soon as its `)` is read, with `<name> expects 1 argument, got <n> at <i>` (for `abs`, `sqrt` and `round`) or `<name> expects at least 1 argument, got 0 at <i>` (for `min` and `max`), where `<i>` is the position of the function's name.
- The whole `source` is parsed before anything is evaluated: a syntax error (every error above) wins over any error of evaluation, wherever it is in `source`.

Values
- `vars` may be left out, which is the same as `{}`. A name is a variable defined by `vars` only when `vars` has it as an own property (`Object.hasOwn`); inherited properties such as `toString` or `constructor` never count. The tests only give `vars` own properties whose values are finite numbers.
- The variables `pi` and `e` are `Math.PI` and `Math.E`, unless `vars` defines them. Any other variable that `vars` does not define fails with `unknown variable <name> at <i>`. Function names are not variables: `abs` alone is an unknown variable unless `vars` defines it, and `vars` never changes what a call does.
- `+`, `-`, `*` and `/` are JavaScript's, `%` is JavaScript's remainder (its sign is the sign of the left operand: `-7 % 3` is -1) and `x ^ y` is JavaScript's `x ** y`. `abs`, `sqrt`, `min` and `max` are `Math.abs`, `Math.sqrt`, `Math.min` and `Math.max`. `round(x)` rounds to the nearest whole number, and a value exactly halfway rounds away from zero: `round(2.5)` is 3, `round(-2.5)` is -3 and `round(0.49999999999999994)` is 0.
- Evaluation goes from left to right: an operator evaluates its left operand, then its right one, then itself; a call evaluates its arguments in order, then itself. The first failure stops `evaluate`:
  - `/` or `%` with a right operand of 0 fails with `division by zero at <i>`, where `<i>` is the position of the operator.
  - An operator or a function whose result is not a finite number (for example `10^400`, `0^-1`, `sqrt(-1)` or `(-8)^(1/3)`) fails with `result is not a finite number at <i>`, where `<i>` is the position of the operator or of the function's name.
- `evaluate` returns a finite number. When the value is -0 it returns 0 instead. It never changes `vars`.

Errors
- `CalcError` is a subclass of `Error` whose `name` is `CalcError`. Every error above is thrown as a `CalcError` with exactly the message given, and with a `position` property: the number `<i>`, or `null` for `unexpected end of input`.
- When `source` is not a string (a String object included), `evaluate` throws a `TypeError` with the message `source must be a string`.
- The tests never pass a `source` longer than 100000 characters, or one with more than 500 levels of parentheses, signs or `^`. A run of `+` and `-`, or of `*`, `/` and `%`, at one level is not nesting however long it is: a sum of 50000 numbers must work.

Command line
- `node calc-cli.mjs <expression> [<name>=<value>]...`: the first argument is the expression, each later one defines a variable. No argument is an option: `node calc-cli.mjs -2*3` evaluates `-2*3`.
- A `<name>=<value>` argument has a name as defined under Tokens, then `=`, then a value: an optional `-` followed by a number as defined under Tokens, with a finite value. Nothing else is allowed in the argument (no white space).
- On success, write the value and "\n" to stdout, write nothing to stderr, and exit 0. The value is written with at most 12 significant digits, as `String(Number(value.toPrecision(12)))` gives it, so `0.1+0.2` prints `0.3`, `1/3` prints `0.333333333333` and `10^21` prints `1e+21`.
- Errors write exactly one line to stderr, ending in "\n", write nothing to stdout, and are checked in this order:
  - No arguments at all: `Usage: node calc-cli.mjs <expression> [<name>=<value>]...`, exit 2.
  - The variable arguments, from left to right: one that is not a `<name>=<value>` argument is `Error: bad variable <argument>` (the argument as given), and a name given a second time is `Error: variable <name> given twice`; each exits 2.
  - `evaluate` throws a `CalcError`: `Error: <message>`, exit 1.
