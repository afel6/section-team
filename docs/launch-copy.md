# Launch copy for 0.6.0

What a post, a listing or a reply about section-team 0.6.0 may claim, with the number, sample size, judge and source behind each claim, and what it must not claim, with the reason. Round nx numbers come from `node bench/data/nx/recompute.mjs` (cost, wall time, Codex means, hidden tests, near-misses) and `bench/data/nx/bars-nx.json` (the bars). Older rounds' numbers come from their own folders under `bench/data/`.

## Read this first

These facts limit every claim below.

1. **No round measured the released 0.6.0.** Round nx ran `v0.6.0-rc.1`, which included the Balanced direct tier (L1: the supervisor makes a small fix itself and the Opus reviewer grades it). L1 missed its quality bar and was reverted before release (commit `7dd5bf3`). 0.6.0 is rc.1 without L1, plus docs, data and label changes.
2. **The nearest measured build differs by task.** On h8, the small fix, it is v0.5.1 (the base arm), because 0.6.0 routes small fixes as v0.5.1 did. On h9 and h10 L1 never fired, so rc.1 (the team arm) is nearest.
3. **One judge.** Codex (gpt-6.1-sol, ultra effort) judged blind, one fresh read-only session per case: 18 cases, 9 groups, each seen in both mirrored orders. Its sandbox blocked test suites that spawn a CLI or make temp folders, so it ran the in-process suites and its own probes.
4. **Few runs.** h8 has 5 groups (5 runs per setup); h9 and h10 have 2 each.
5. **The tasks** were written by Claude agents in the week of the round. The sections' rules were not tuned on them. h8 is a small single-area fix, h9 a single-area build, h10 a multi-area build. The tasks, hidden tests, bars and harness were frozen in the public tag `nx-freeze` before the first paid run.

Setups: **solo** is plain Claude Code (plugin off) on the round's clean profile. **base** is section-team v0.5.1. **team** is v0.6.0-rc.1. Both plugin setups ran in Balanced. There was no Max arm.

## Say it this way

> section-team 0.6.0 is an MIT-licensed Claude Code plugin that hands each job to an Opus specialist agent and has a hook check that a section's "done" hand-back of changed code carries a passing grade from an Opus reviewer. In round nx, frozen in a public tag before the runs (5, 2 and 2 runs per setup on three tasks), the builds nearest to 0.6.0 cost about 7× plain Claude Code's usage in Balanced, the default; Max costs about 10×, measured on earlier 0.3.0+ rounds and not on 0.6.0. Judged blind by one judge (Codex), v0.5.1, the build nearest to how 0.6.0 handles small fixes, scored 8.44 against plain Claude Code's 7.44 out of 10 on a small fix (5 groups, reported, no bar), at 2.92× the cost; every setup passed every hidden test, so no correctness gain was shown. A release-candidate change that made small fixes cheaper missed its pre-set quality bar (5 groups, Codex) and was reverted before release, as the round's rule required. The raw data and a script that reprints the round's tables are in `bench/data/nx/`, and `/team mode off` turns the plugin off in one project.
