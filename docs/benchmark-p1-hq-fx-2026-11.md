# Benchmark results in detail: round 17 and the p1, hq and fx rounds (2026-10 to 2026-11)

The README gives the short version. This file keeps every round's numbers, targets and judge findings, moved here from the README so the README stays short.

**Which numbers you can recompute.** Raw data is published for rounds 1 to 17 and the held-out round ([`bench/data/`](../bench/data/), [`bench/data/heldout/`](../bench/data/heldout/)), the mode round ([`bench/data/modes/`](../bench/data/modes/)) and the p1 rounds listed in [`bench/data/p1/`](../bench/data/p1/). Those p1 rounds are the 0.2.3 round, the 0.3.0 round, the confirm and measure rounds and rounds tg to to (tk was void): `node bench/data/p1/recompute.mjs` prints their costs, hidden-test means and judge scores, and `node bench/data/p1/recompute.mjs ph py` prints rounds ph and py from [`bench/data/ph/`](../bench/data/ph/) and [`bench/data/py/`](../bench/data/py/). The held-out round hq is in [`bench/data/hq/`](../bench/data/hq/) (`node bench/data/hq/recompute.mjs`) and the fx check in [`bench/data/fx/`](../bench/data/fx/) (`node bench/data/fx/recompute.mjs`). Rounds py, ph and hq ran on a second test machine. Not published: the quiet rescore of round tj (a reported rescore, not published) and the 0.2.3 h7 cost runs. The targets of the p1, hq and fx rounds were set before each round but recorded privately, not in a public freeze tag, so they are not publicly pre-registered; only the held-out round (tag `heldout-freeze`) and the mode round (tag `mo-freeze-cloud`, `bench/bars-mo.json`) are.

**Baselines.** Solo is Claude Code with the plugin off. Only the mode round's baseline was plain Claude Code on a clean machine. In rounds 1 to 17, the held-out round and the p1 rounds on the main test machine (the ten in `bench/data/p1/`) it was Claude Code with the author's setup (plugin off; their CLAUDE.md and other plugins on): 16 of the 20 solo runs in `bench/data/p1/` and 5 of the 9 held-out ones spawned the author's code-reviewer or security-reviewer agent. For rounds py, ph, hq and fx the machine setup was not recorded, so their solo rows say so; none of their 16 solo runs spawned a reviewer agent.

**Round 17 (in-sample tuning, v0.1.x).** The plugin was tuned for 17 rounds on these same three tasks, and in that version the supervisor still built small and single-area work itself. Its baseline, "plain Claude Code (plugin off)", was the author's own setup: their global CLAUDE.md and other plugins stayed on ([details](benchmark-2026-10-24.md)).

Measured over 17 benchmark rounds (three tasks of rising size, two runs each, graded blind by 12 Opus judges per round). In the final round:

| | Cost per task | Judge quality (1–10) | Ranked 1st / last (of 12 judges) |
|---|---|---|---|
| Plain Claude Code (plugin off, author's setup) | $0.85 | 7.1 | 0 / 9 |
| An earlier version of this team | $3.39 | 7.7 | 0 / 3 |
| **section-team (round 17)** | $3.10 | **8.6** | **12 / 0** |

Across the later pre-registered rounds on new tasks (the held-out round and the mode round), the default mode cost about 2.2 to 5.2 times as much as solo, and about 7.5 to 9.7 times in Max, depending on the tasks and the setup (the Max range comes from the mode round only, which also measured Lean, removed in 0.3.0; see [Modes](../README.md#modes)), for code that blind judges rated higher, with tests the largest part of the gap (42 to 44% in the mode round). On the multi-area task, the one closest to a real platform, the mode round measured Lean 4.5, Balanced 7.0 and Max 13.4 times plain Claude Code ([details](benchmark-modes-2026-11.md)). The table above is the final tuning round; the later rounds on new tasks are the fairer guide.

**Limits:** every setup, solo included, passed all the hidden tests, so the gains are in blind-judged quality, not in whether the code works. Each cell is 2 runs (about ±0.3 judge noise), and the team was tuned over 17 rounds on these same three tasks. A pre-registered held-out round on three new tasks it had never seen measured a smaller gain that still cleared the bar set in advance: blind judge quality 8.8 against 8.2 for solo (the author's setup), both passing every hidden test, at about 2.2 times the cost ([details](benchmark-heldout-2026-11.md)). A later pre-registered round on a clean machine measured the default mode at 8.8 against 7.4, at about 5.2 times the cost ([details](benchmark-modes-2026-11.md)). Round hq (below), on three tasks not judged since 0.3.0, missed two of its pre-set bars: the default mode was 0.67 (Codex) and 1.33 (Fable) above solo, against 1.0 on both, at 5.2 times the cost, against at most 5; Max was 1.50 and 1.83 above it at 10.5 times. On that round's platform task, solo and the default mode passed 146 and 147 of the 148 hidden tests on average, and Max all 148. Fable also planned and reviewed some of the fixes it judged.

Balanced was ranked first in every judged group. Lean was barely ahead of solo. Max was slower and no better: one Max run timed out in stage 3. **A check of one Balanced fix on three new tasks (fx, 2026-11-20).** Raw data: [`bench/data/fx/`](../bench/data/fx/) (`node bench/data/fx/recompute.mjs`). Round hq put Balanced's Codex gap down to test strength, so commit 4b07ff0 (branch `fix/balanced-gap-list`) changed single-area Balanced work: a passing grade lists test gaps, and the builder adds those tests. Round fx compared it with Balanced as released (v0.4.0) and with solo (machine setup not recorded) on three new single-area tasks written blind for the round (f1 a time-log tool with seeded bugs and a new check command, f2 a cron next-run tool, f3 a poll API), two runs per setup, judged blind by Codex and Fable (12 cases each). Means, solo / Balanced / Balanced with the fix: Codex 7.83 / 9.08 / 9.08, Fable 6.58 / 8.58 / 8.33. Both Balanced setups passed every hidden test in every run (28, 30 and 28), and solo missed one in one run; the fix cost 2.93× solo and 1.02× Balanced without it. In every fix run the grader listed test gaps (in one, through a failing grade that also led to a code fix) and the tests were added; without the fix none were listed. The fix was ahead on f1 on both judges (Codex 10.00 against 9.00, Fable 9.00 against 8.00), behind on f2 on both, and behind on f3 for Fable (level for Codex). Its bar, set before the round, was never below Balanced on either judge and ahead on at least one; it tied on Codex and was 0.25 lower on Fable, so the fix does not ship. On these smaller tasks Balanced as released was 1.25 (Codex) and 2.00 (Fable) above solo. Limits: two runs per setup; the hidden tests could not separate the two Balanced setups. Fable also planned and reviewed some of the fixes it judged.

**Method:** rounds 1 to 17 build the same three tasks (a small library, a command-line tool and a web app) twice per setup; hidden tests check correctness, then the solutions are anonymised and graded blind by Opus judges on correctness, code quality, tests, robustness and docs. The p1 rounds build one platform task in three stages, and the hq and fx rounds three tasks each; their solutions are judged blind by Codex and, from the measure round on, by Fable too. The tasks, hidden tests, harness and scorer are in [`bench/`](../bench/). Raw scores are published only for the rounds named at the top of this file; a round runs real paid Claude sessions. Full results and every round's changes: [docs/benchmark-2026-10-24.md](benchmark-2026-10-24.md) (final summary at the end).
