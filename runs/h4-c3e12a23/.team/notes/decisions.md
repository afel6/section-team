# Decisions — 2026-11-02
- Source of truth: `.team/notes/spec.md` (verbatim user spec). Where a line reads two ways, build the stricter reading and record it here.
- Only Node.js built-ins; no npm install; never use the Fable model.
- File layout: `server.mjs` at root (backend). Page files `public/index.html` and `public/app.js` (frontend). server.mjs locates them relative to its own folder via `new URL('./public/...', import.meta.url)` (NOT cwd).
- Data file layout (backend owns): `{"nextId": <int>, "bookings": [ ... ]}`.
- Tests: `test/*.test.mjs` using node:test; package.json `"test": "node --test"` (finds test/ files). Server tests spawn `node server.mjs` with PORT=0 and a temp DATA_FILE in a temp dir. Frontend tests run `public/app.js` in `node:vm` with a fake DOM + fake fetch (no npm).
- package.json: `{"type":"module","scripts":{"start":"node server.mjs","test":"node --test"}}` (backend creates it).
- Near-miss copies only in `.team/near-miss/`.
- 2026-11-02 · frontend · `?date=<value>` is appended raw (no encodeURIComponent) — spec says "the value unchanged". GETs pass `{ method: 'GET' }`. A Cancel click while that button is disabled sends nothing (matches browser behaviour; same guard as Book). A 200 list/rooms reply without an array shows `Request failed.` instead of throwing.
- 2026-11-02 · backend · "data in the layout this server writes" read strictly: exact keys `nextId`/`bookings`, every booking valid by the POST rules (trimmed title, exact keys, id < nextId, unique ids, no overlaps) — anything else is `cannot read data file`. Data file is written in place (no temp file + rename) because the spec allows writing only the data file. Every request (GET included) runs through one FIFO queue after its body is fully read.
- 2026-11-02 · testing · Page element "text" (title, h1, labels, buttons) is compared exactly, with no trimming: `<label for="room"> Room </label>` would fail. "Error status" means any status other than the request's exact success status (200/201/204), so tests also send 200 to a POST, 201/204 to GETs and 200/201 to a DELETE. The test harness always frames string/Buffer bodies with Content-Length, because Node's client does not do this for DELETE/GET. Without it a body was sent unframed and the connection was reset, which is a client artifact and not a server bug.
- 2026-11-02 · testing · Strict reading of "whatever the method" and "the client always receives the reply": a CONNECT request is routed like any other method (`CONNECT /api/rooms` → 405, an authority-form target → 404 `not found`). A request with an unknown `Expect` value gets its route's normal reply (body read first), not Node's automatic 417. Tests: `test/server-edge-requests.test.mjs`.
