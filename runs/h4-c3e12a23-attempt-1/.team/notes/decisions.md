# Decisions — owner: supervisor

- File layout: `server.mjs` (backend), `public/index.html` + `public/app.js` (frontend; server reads them and serves at `GET /` and `GET /app.js`, resolved relative to server.mjs via import.meta.url), `test/*.test.mjs` (testing), `package.json` (`"type": "module"`, `"start": "node server.mjs"`, `"test": "node --test test/"`), `README.md` (docs).
- Data file layout: `{"nextId": <int>, "bookings": [ {id, room, title, date, start, end}, ... ]}`. On load, validate strictly (object, integer nextId >= 1, bookings array of well-formed bookings with id < nextId); anything else → `cannot read data file <name>`.
- Save: write a temp file next to the data file then rename (atomic); a failed save rolls back memory. All mutations serialized through one in-process queue/lock.
- Strict readings: where a spec line reads two ways, build the stricter reading.
- 2026-11-02 · frontend · A success-status reply (200) whose JSON lacks the expected `rooms`/`bookings` array shows `Request failed.` in `#error` and changes nothing else (latest list fetch only). Why: spec is silent; avoids an uncaught TypeError and matches the "error message otherwise" fallback.
- 2026-11-02 · frontend · `node --test test/` (directory arg) fails with MODULE_NOT_FOUND on this Node 22.23; the package.json "test" script should be `node --test` (default discovery) or a glob. Why: verified by running it.
- 2026-11-02 · backend · package.json "test" is `node --test "test/**/*.test.mjs"` (glob, not default discovery). Why: `node --test test/` fails on Node 22; default discovery would also run `test/helpers/*.mjs` and any `.team/near-miss/` copies matching `*.test.mjs`. Test files must be named `*.test.mjs`.
- 2026-11-02 · backend · Strict readings: ENOTDIR on DATA_FILE is not ENOENT (gives `cannot read data file`); HEAD on known paths is 405; a data file with overlapping, duplicate-id, untrimmed-title or extra-key bookings is an invalid layout. Why: build the stricter reading.
- 2026-11-02 · testing · Tests assert the stricter readings: a data file with an extra top-level key, or a UTF-8 BOM before valid JSON, is not this server's layout (exit 1, `cannot read data file <name>`); `​` is a valid 1-unit title (String.prototype.trim keeps it); a Content-Type padded with U+00A0 is 415 (only spaces/tabs are stripped). Why: the server writes exactly `{nextId, bookings}` with no BOM, and the spec names trim() for titles but spaces/tabs for the media type.
- 2026-11-02 · testing · Child-process tests wait for `'close'`, not `'exit'`, before reading stdout/stderr; raw-TCP requests do not half-close the socket. Why: `'exit'` can fire before stdio drains (flaky empty stderr), and node:http aborts a request whose client sent FIN before the reply.
