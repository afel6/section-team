This repo is a small command-line tool that reports the time logged per project in a plain text time log (see README.md), and its tests pass. Work on it as you would on a teammate's project.

Problems users reported
1. "I logged `2026-03-06 23:30-00:30 release` for a late deploy, and the report shows `release	-23:0` instead of one hour."
2. "`report work.log --to 2026-03-05` leaves out everything I logged on March 5."
3. "A project with 65 minutes shows as `1:5`, and an empty log shows `total	0:0`."

README.md describes how the tool is meant to work: where the code disagrees with it, the code is wrong. Fix the code, not the README's rules.

Feature request
- Add a command `node timelog.mjs check <file>`. Its logic goes in a new module `lib/check.mjs`, exported under any name; the hidden checks run the tool as a process only.
- `check` takes exactly one argument, the file. With no file, or with anything after the file (an option included), it gets the same usage error as `report`: the exact line `usage: node timelog.mjs report <file> [--from <date>] [--to <date>]` on stderr, nothing on stdout, exit 2. The usage text does not change.
- The file is read, decoded and parsed exactly as for `report`, with the same rules, the same error lines and the same exit codes (3 for `cannot read` and `is not valid UTF-8`, 4 for `line <n>: <reason>`). `check` has no date range: every entry in the file counts, whatever its date or project.
- An entry covers the time from its start to its end, where an entry whose end is earlier than its start ends on the next day (as the README says). Entries on different dates are compared on one time line, so `2026-03-01 23:00-01:00 a` covers the first hour of 2026-03-02, and an entry on 2025-12-31 that runs past midnight covers part of 2026-01-01. Two entries overlap when they share more than 0 minutes; an entry that ends at 10:00 and one that starts at 10:00 on the same date do not overlap. Two identical entries overlap for their whole length.
- When no two entries overlap, `check` writes one line, `no overlaps in <n> entries`, where `<n>` is the number of entries in the file (blank lines and comments do not count), and exits 0. When `<n>` is 1 the line is `no overlaps in 1 entry`; an empty file, or one with only blank lines and comments, gives `no overlaps in 0 entries`.
- When at least one pair overlaps, `check` writes one line per overlapping pair, `line <a> overlaps line <b> by <H:MM>`, where `<a>` and `<b>` are the line numbers of the two entries in the file (counted as the README counts them), `<a>` is the smaller one, and `<H:MM>` is the time they share in the README's duration format (for example `by 0:05` or `by 1:30`). Lines are sorted by `<a>`, then by `<b>`, both ascending. At most 50 pair lines are written: when there are more than 50 overlapping pairs, the first 50 in that order are followed by one line `and <k> more`, where `<k>` is the number of pairs not shown; with exactly 50 pairs there is no such line. It then exits 1.
- In both cases each line ends in `\n`, stderr stays empty, and nothing else is written.

Keep the existing tests passing, add tests with node:test for your changes (the `package.json` "test" script must run them all), and document `check` in the README: it must contain the literal text `node timelog.mjs check <file>`, the line format `line <a> overlaps line <b> by <H:MM>`, the limit line `and <k> more`, and exit codes 0 and 1 for `check`.
