Build a command-line tool `ini2json.mjs` (an ES module, run as `node ini2json.mjs <file>`) that converts an INI file to JSON.

Output
- On success, write `JSON.stringify(result, null, 2)` followed by "\n" to stdout, write nothing to stderr, and exit 0.
- `result` is an object. Keys that come before the first section header are top-level keys of `result`. Each section is a key of `result` whose value is an object holding that section's keys. Keys and sections keep the order in which they first appear in the file. An empty file gives `{}`.

Input
- The file is read as UTF-8: a byte order mark (U+FEFF) at its very start is ignored, and bytes that are not valid UTF-8 become U+FFFD (that is not an error). Lines end in "\n" or "\r\n"; a "\r" that is not followed by "\n" is an ordinary character. Line numbers start at 1 and count every line, including blank and comment lines.
- Spaces and tabs at the start and end of a line are ignored. A line that is then empty, or that starts with `;` or `#`, is skipped.
- A line that starts with `[` is a section header. It must be exactly `[`, a name, and `]`; spaces and tabs between the brackets and the name are ignored. Keys after it belong to that section until the next header. A section may appear more than once: its keys are merged into the first one.
- Any other line must be `key = value`: the key is the text before the first `=`, the value is the text after it, each without the spaces and tabs around it. The value may be empty.
- Section names and keys are 1 to 64 characters from A-Z, a-z, 0-9, `_`, `-` and `.`, and start with a letter or `_`. Letter case matters, and a dot is an ordinary character (no nesting). Every valid name is an ordinary key of the output, `__proto__` and `constructor` included.
- `;` and `#` inside a value are part of the value: there are no inline comments.

Values
- A value that starts with `"` is quoted. It must end with the `"` that closes it, with nothing after that quote. Inside the quotes, `\"` stands for `"` and `\\` stands for `\`; any other `\`, and any `"` that is not escaped, is an error. A quoted value is always a string, with its inner spaces kept.
- Any other value: exactly `true` or `false` becomes a boolean. `0`, or an optional `-` followed by a digit 1-9 and then any digits, becomes a number when it is from -9007199254740991 to 9007199254740991 inclusive, and stays a string otherwise. Everything else, the empty value included, is a string.

Errors (exactly one line to stderr, ending in "\n"; nothing to stdout)
- Not exactly one argument: `Usage: node ini2json.mjs <file>`, exit 2.
- The file does not exist: `Error: <file>: no such file`. It is a directory: `Error: <file>: is a directory`. Any other read error: `Error: <file>: cannot read`. Each exits 1; `<file>` is the argument as given.
- The first invalid line stops the tool with `Error: line <n>: <reason>` and exit 3, where `<reason>` is the first of these that applies to that line:
  - `bad section name` for a section header that breaks the rules above;
  - `missing =` for any other line that has no `=`;
  - `bad key` for a key that breaks the rules above;
  - `bad quoted value` for a quoted value that breaks the rules above;
  - `duplicate key <key>` when the key is already in the same place: among the top-level keys for a key before the first section header, otherwise in the current section (keys under an earlier header with the same name included). A key in a section may have the same name as a top-level key or a section;
  - `conflict <name>` for a section header whose name is already a top-level key.
